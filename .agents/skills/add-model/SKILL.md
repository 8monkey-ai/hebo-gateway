# Add Model or Provider

The model catalog is **not** maintained in this repo. It comes from [models.dev](https://models.dev):

- At runtime the gateway loads `https://models.dev/api.json` once (first request) and converts it with `fromModelsDev` (`src/models/models-dev.ts`).
- If that fails it falls back to the snapshot bundled with the release, `src/models/models-dev.json`, generated by `bun run models:sync` (also run by `prepublishOnly`).

So a new model usually needs **no change here**. Changes are needed when:

- a provider cannot translate the model's canonical ID into its native ID (provider mapping),
- the model needs request translation (model or provider middleware),
- a new lab or provider is added (`HOSTS` / `LABS` / `FIRST_PARTY` in `src/models/models-dev.ts`),
- models.dev is missing or wrong about the model (fix it upstream; consumers can use `models.overrides` meanwhile).

## When to Use

- A model is on models.dev but a provider does not serve it through the gateway
- Adding or updating a model-family middleware (reasoning, caching, dimensions, transcription)
- Adding a new provider adapter or lab
- Refreshing the bundled snapshot

## Step 1: Find the Model on models.dev

The full `api.json` (~7 MB) is `{ [provider]: { models: { [nativeId]: {...} } } }`. Grep instead of loading it:

```bash
# Every listing of a model, with its provider-native ID and canonical ID
curl -s 'https://models.dev/api.json' | jq -c 'to_entries[] | .key as $p | .value.models | to_entries[]
  | select((.value.canonical_model_id // .key) | test("<SEARCH_TERM>")) | {provider: $p, id: .key, canonical: .value.canonical_model_id, status: .value.status, type: .value.type}'
```

Relevant fields: `canonical_model_id` (`<lab>/<model>`), `status` (`deprecated` listings are ignored), `type` (`embedding` / `transcription`; image, video, speech, ... are ignored), `release_date`, `knowledge`, `limit.context`, `modalities`, `attachment`, `reasoning`, `tool_call`, `structured_output`, `temperature`, `open_weights`.

The canonical ID used by the gateway is the models.dev one (`canonical_model_id`, or `<lab>/<id>` for first-party listings without it), e.g. `anthropic/claude-sonnet-4-6`, `moonshotai/kimi-k3`, `zhipuai/glm-5.3`, `minimax/MiniMax-M3`. Do not invent IDs.

Then refresh the snapshot and check the entry:

```bash
bun run models:sync
jq '."<canonical-id>"' src/models/models-dev.json
```

`providers` lists every gateway provider models.dev knows serves it, lab first.

## Step 2: Make Every Provider Able to Serve It

At startup, `normalizeCatalog` drops providers whose adapter cannot resolve the model (`getCanonicalIdsResolver`): an ID is served when it is in the adapter's mapping, or its namespace is in the adapter's `namespaces`.

| Adapter                                                                  | Default (`namespaces`)                                                                 |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| anthropic, openai, cohere, deepseek, minimax, moonshot, voyage, xai, zai | Own lab only; native ID = canonical ID without namespace                               |
| vertex                                                                   | `google`, `anthropic`                                                                  |
| alibaba, azure                                                           | Every namespace (Azure: deployment name = model name)                                  |
| bedrock                                                                  | `amazon` only (Nova); everything else, plus Mantle (`MANTLE_MAPPING`), needs a mapping |
| chutes, deepinfra, fireworks, groq, togetherai                           | None: mapping only                                                                     |

For each provider in the entry's `providers`:

1. Open `src/providers/<provider>/canonical.ts`.
2. Take the native ID from the models.dev listing of that provider (Step 1), and cross-check the provider docs (Bedrock: on-demand vs inference profile `{ip}`, Mantle; Vertex: `@` versions, MaaS).
3. If the default transform does not produce it, or the namespace is not derived, add a `MAPPING` entry.
4. Add a case to `src/providers/<provider>/canonical.test.ts`.

### Canonicalization options reference

```typescript
type CanonicalIdsOptions = {
  mapping?: Partial<Record<ModelId, string>>; // Explicit canonical → native mappings
  namespaces?: readonly string[]; // Namespaces the default transform handles (default: all)
  options?: {
    stripNamespace?: boolean; // Remove "lab/" prefix (default: true)
    normalizeDelimiters?: boolean | string[]; // Convert "." → "-" (default: false)
    prefix?: string; // Prepend to transformed ID
    template?: Record<string, string>; // Template variable substitution
    postfix?: string; // Append to transformed ID
    namespaceSeparator?: "/" | "." | ":"; // Namespace delimiter (default: "/")
  };
};
```

## Step 3: Check Whether Middlewares Are Needed

Middlewares bridge OpenAI-compatible request parameters to provider-native options. They exist at **two levels** — both must be checked. All model-level middleware is registered by `src/models/middleware.ts`.

### Model-level middlewares (`src/models/<lab>/middleware.ts`)

Registered via `modelMiddlewareMatcher.useForModel()` and matched by canonical model ID patterns.

| Category       | When needed                                                                             | Example                                                                                         |
| -------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Reasoning**  | Model supports extended thinking / chain-of-thought (`reasoning` in `capabilities`).    | `claudeReasoningMiddleware` maps `reasoning.effort` → Anthropic `thinking` / `effort` options   |
| **Dimensions** | Embedding model supports variable output dimensions with a non-standard parameter name. | `voyageDimensionsMiddleware` maps `dimensions` → Voyage `outputDimension`                       |
| **Caching**    | Model supports prompt caching (`cost.cache_read` / `cost.cache_write` on models.dev).   | `claudePromptCachingMiddleware` maps `cache_control` → Anthropic `cacheControl` provider option |

1. Check whether an existing pattern already matches the canonical ID (e.g. `anthropic/claude-opus-5*`).
2. If not, extend the `useForModel()` patterns, or create `src/models/<lab>/middleware.ts` (and import it from `src/models/middleware.ts` and `src/models/<lab>/index.ts`; add the `./models/<lab>` export to `package.json`).
3. Add or update tests in `src/models/<lab>/middleware.test.ts`.

### Provider-level middlewares (`src/providers/<provider>/middleware.ts`)

Registered via `modelMiddlewareMatcher.useForProvider()` and matched by provider ID.

| Category          | Providers with middleware   | What it does                                                                                                    |
| ----------------- | --------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Service tiers** | `bedrock`, `vertex`, `groq` | Maps OpenAI `service_tier` values to provider-native equivalents (e.g., `"scale"` → Bedrock `"reserved"`)       |
| **Reasoning**     | `bedrock`, `fireworks`      | Translates reasoning params into provider-native format (e.g., Bedrock `reasoningConfig`, Fireworks `thinking`) |
| **Caching**       | `bedrock`                   | Maps `cache_control` → Bedrock `cachePoint` with provider-specific TTL handling                                 |

Some middlewares filter internally by native model ID (e.g. `bedrockPromptCachingMiddleware` only applies to `nova` and `claude`); update those filters when needed.

## Step 4: New Lab or Provider

- **New lab** (canonical namespace): add it to `LABS` in `src/models/models-dev.ts` (with the gateway provider it runs, or `null`), and to `FIRST_PARTY` if models.dev has a first-party provider for it. Models of labs not in `LABS` are left out of the catalog.
- **New provider adapter**: add it to `CANONICAL_PROVIDER_IDS` (`src/providers/types.ts`), map it to its models.dev provider ID(s) in `HOSTS` (key order = provider preference), create `src/providers/<provider>/` with a `withCanonicalIdsFor*` adapter that sets `namespaces`, and add the package export.

Then run `bun run models:sync`.

## Step 5: Write Tests

- Canonical mapping tests: `src/providers/<provider>/canonical.test.ts`
- Middleware pattern tests: `src/models/<lab>/middleware.test.ts`
- Conversion changes: `src/models/models-dev.test.ts`; catalog filtering: `src/models/catalog.test.ts`

## Step 6: Update README

Update `README.md` when a provider adapter is added (Built-in adapters list) or catalog behavior changes (Models section).

## Checklist

- [ ] Canonical ID taken from models.dev
- [ ] `bun run models:sync` run, snapshot entry checked

- [ ] Middlewares checked: reasoning, dimensions, caching, transcription, service tiers
- [ ] `bun run check` passes
