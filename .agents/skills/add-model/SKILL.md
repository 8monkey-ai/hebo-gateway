# Add Model or Provider

The model catalog is **not** maintained in this repo. It comes from [models.dev](https://models.dev), which is also the source of truth for provider-native model IDs:

- At runtime the gateway loads `https://models.dev/api.json` once (first request) and converts it with `fromModelsDev` (`src/models/models-dev.ts`), for the labs that are imported.
- If that fails it falls back to the snapshots bundled with the release, `src/models/<lab>/models-dev.json`, generated by `bun run models:sync` (also run by `prepublishOnly`).
- Each lab module (`src/models/<lab>/presets.ts`) registers its snapshot (and gap-filling extras) with `registerModels`, and exports its model families (`defineModelFamily`).

So a new model usually needs **no change here**. Changes are needed when:

- models.dev does not list the model (yet): add a lab extra, and open an upstream PR,
- the model needs request translation (model or provider middleware),
- the model does not fit its family's `version` pattern or a named group,
- a new lab or provider is added.

Fix wrong data upstream on models.dev. Extras only fill gaps: they are ignored once models.dev lists the same ID, so there is no merging and no way to override upstream data.

## Step 1: Find the Model on models.dev

The full `api.json` (~7 MB) is `{ [provider]: { models: { [nativeId]: {...} } } }`. Grep instead of loading it:

```bash
# Every listing of a model, with its provider-native ID and canonical ID
curl -s 'https://models.dev/api.json' | jq -c 'to_entries[] | .key as $p | .value.models | to_entries[]
  | select((.value.canonical_model_id // .key) | test("<SEARCH_TERM>")) | {provider: $p, id: .key, canonical: .value.canonical_model_id, status: .value.status, type: .value.type, npm: .value.provider.npm}'
```

Relevant fields: `canonical_model_id` (`<lab>/<model>`), `family`, `status` (`deprecated` listings are ignored, `alpha` / `beta` are kept out of `latest`), `type` (`embedding` / `transcription`; image, video, speech, ... are ignored), `provider.npm` (listings served through an SDK the adapter does not speak are ignored, see `HOSTS`), `release_date`, `knowledge`, `limit.context`, `modalities`, `attachment`, `reasoning`, `tool_call`, `structured_output`, `temperature`, `open_weights`.

The canonical ID used by the gateway is the models.dev one (`canonical_model_id`, or `<lab>/<id>` for first-party listings without it), e.g. `anthropic/claude-sonnet-4-6`, `moonshotai/kimi-k3`, `zhipuai/glm-5.3`, `minimax/MiniMax-M3`. Do not invent IDs.

Then refresh the snapshots and check the entry:

```bash
bun run models:sync
jq '."<canonical-id>"' src/models/<lab>/models-dev.json
```

`providers` maps every gateway provider models.dev lists it on to its native ID, lab first. When a provider lists several IDs for a model, `fromModelsDev` picks one:

- **Bedrock**: Converse first (`{ip?}` prefix when inference profiles are listed too, `{ip}` when only profiles are), then Mantle (`mantle:` prefix).
- **Others**: the ID named like the model, then the shortest; Fireworks routers last.

## Step 2: Fill Gaps (only if models.dev lacks the model)

Add the entry to the `extras` of `registerModels` in `src/models/<lab>/presets.ts` (see `microsoft` / `voyage`). `providers` lists the providers serving it, in routing order (same shape as consumer entries). There is no native ID on the entry: providers derive it from the canonical ID (namespace stripped), so only add an extra when that derived ID is what the provider serves. Verify the metadata against the lab's docs; keep it minimal rather than speculative.

## Step 3: Check the Model Family

Families (`src/models/<lab>/presets.ts`) select models by a `version` pattern, resolved when the catalog loads:

- `all`: every model matching `version`; `vX` / `vX.Y` / `vX.x`: by the captured version (`-` reads as `.`).
- `latest`: the newest stable `release_date` per models.dev `family`.
- Named groups: `*` patterns.

Check the new model lands in the expected groups; adjust the pattern or a named group otherwise, and keep `README.md` (Model Families) in sync.

## Step 4: Check Whether Middlewares Are Needed

Middlewares bridge OpenAI-compatible request parameters to provider-native options. They exist at **two levels** — both must be checked.

### Model-level middlewares (`src/models/<lab>/middleware.ts`)

Registered via `modelMiddlewareMatcher.useForModel()` and matched by canonical model ID patterns. They are registered when the lab module is imported.

| Category       | When needed                                                                             | Example                                                                                         |
| -------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Reasoning**  | Model supports extended thinking / chain-of-thought (`reasoning` in `capabilities`).    | `claudeReasoningMiddleware` maps `reasoning.effort` → Anthropic `thinking` / `effort` options   |
| **Dimensions** | Embedding model supports variable output dimensions with a non-standard parameter name. | `voyageDimensionsMiddleware` maps `dimensions` → Voyage `outputDimension`                       |
| **Caching**    | Model supports prompt caching (`cost.cache_read` / `cost.cache_write` on models.dev).   | `claudePromptCachingMiddleware` maps `cache_control` → Anthropic `cacheControl` provider option |

1. Check whether an existing pattern already matches the canonical ID (e.g. `anthropic/claude-opus-5*`).
2. If not, extend the `useForModel()` patterns.
3. Add or update tests in `src/models/<lab>/middleware.test.ts`.

### Provider-level middlewares (`src/providers/<provider>/middleware.ts`)

Registered via `modelMiddlewareMatcher.useForProvider()` and matched by provider ID.

| Category          | Providers with middleware   | What it does                                                                                                    |
| ----------------- | --------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Service tiers** | `bedrock`, `vertex`, `groq` | Maps OpenAI `service_tier` values to provider-native equivalents (e.g., `"scale"` → Bedrock `"reserved"`)       |
| **Reasoning**     | `bedrock`, `fireworks`      | Translates reasoning params into provider-native format (e.g., Bedrock `reasoningConfig`, Fireworks `thinking`) |
| **Caching**       | `bedrock`                   | Maps `cache_control` → Bedrock `cachePoint` with provider-specific TTL handling                                 |

Some middlewares filter internally by native model ID (e.g. `bedrockPromptCachingMiddleware` only applies to `nova` and `claude`); update those filters when needed.

## Step 5: New Lab or Provider

- **New lab** (canonical namespace):
  1. Add it to `LABS` in `src/models/models-dev.ts` (with the gateway provider it runs, or `null`), and to `FIRST_PARTY` if models.dev has a first-party provider for it.
  2. Add it to `LABS` in `scripts/sync-models-dev.ts` and run `bun run models:sync`.
  3. Create `src/models/<lab>/presets.ts` (`registerModels` + families) and `index.ts`, add its snapshot to `CanonicalModelId` (`src/models/types.ts`), the `./models/<lab>` export to `package.json`, and the import to `test/helpers/catalog.ts`.
- **New provider adapter**: add it to `CANONICAL_PROVIDER_IDS` (`src/providers/types.ts`), map it to its models.dev provider ID(s) in `HOSTS` with the SDKs it speaks besides the default (key order = provider preference), create `src/providers/<provider>/` with a `withCanonicalIdsFor*` adapter (only provider-wide rules: native IDs come from the catalog), add the package export and a case to `src/providers/catalog-ids.test.ts`.

### Canonicalization options reference

```typescript
type CanonicalIdsOptions = {
  mapping?: Partial<Record<ModelId, string>>; // Explicit canonical → native IDs, win over the catalog
  // Transform for IDs neither `mapping` nor the catalog knows:
  options?: {
    stripNamespace?: boolean; // Remove "lab/" prefix (default: true)
    normalizeDelimiters?: boolean | string[]; // Convert "." → "-" (default: false)
    prefix?: string; // Prepend to transformed ID
    template?: Record<string, string>; // `{key}` substitution, also in catalog / mapping IDs
    postfix?: string; // Append to transformed ID
    namespaceSeparator?: "/" | "." | ":"; // Namespace delimiter (default: "/")
  };
};
```

## Step 6: Write Tests

- Native IDs for every bundled model and provider: `src/providers/catalog-ids.test.ts`
- Provider-wide rules: `src/providers/<provider>/canonical.test.ts` (use `loadBundledCatalog` from `test/helpers/catalog.ts`)
- Middleware pattern tests: `src/models/<lab>/middleware.test.ts`
- Conversion changes: `src/models/models-dev.test.ts`; catalog / families: `src/models/catalog.test.ts`

## Step 7: Update README

Update `README.md` when a provider adapter is added (Built-in adapters list), a family or named group changes (Model Families), or catalog behavior changes (Models section).
